# Retain / Refactor / Rebuild Matrix

Synthesizes `PROPVIEW_SCREENSHOT_AUDIT.md` (what PropertyVault needs to support, evidenced from the reference product) against `EXISTING_CODEBASE_AUDIT.md` (what the PropVault codebase actually has). Decisions use the master prompt's vocabulary: **Retain unchanged / Retain and extend / Refactor / Migrate / Replace frontend / Replace backend / Partial rebuild / Full rebuild / Exclude from Version 1**.

**V1 scope status: confirmed 2026-07-29** (see "Scope decisions — resolved" near the end of this document). The full V1 priority order lives in `ROADMAP.md`. Everything in this document — both the retain/rebuild call and the V1/V2 scope split — is now settled and drives implementation order.

## Scope decisions — resolved 2026-07-29

All five open questions from the first pass of this document have been confirmed by Mohammed:

1. **Target jurisdiction: South Africa, specifically.** Compliance modules (Trust & Deposits/RHA, Tax Pack/SARS, Organisation profile fields for CIPC/VAT/POPIA/FFC) are real V1 features, built for South African rules, not a generic placeholder.
2. **V1 scope, adjusted from the original proposal**: Tax Pack and a simplified Portfolio Map move **into** V1 (see their rows above). Listings Studio, Enquiries/Leads, Articles, Sales & Auctions, Virtual Tours, Neighbourhood, and Valuations stay **excluded from V1** — Articles and Sales & Auctions explicitly remain on the roadmap for a later phase rather than being dropped as out-of-scope. Tasks & Reminders gets **no standalone module**; task workflows are implemented inline within Maintenance, Inspections, Lease renewals, Documents, Payments, and Compliance instead. Full V1 priority order is in `ROADMAP.md`.
3. **Vendor portal: none for V1.** Staff/landlord captures vendor bills on the vendor's behalf.
4. **WhatsApp/Email provider accounts**: still a genuine external-service blocker — I cannot create these accounts myself. Both are confirmed V1 scope regardless (per the priority order), sequenced late enough that account provisioning can happen in parallel with earlier build work. When ready, I'll need the provisioned credentials set as environment variables, never pasted into chat.
5. **Accounting engine: build in-house.** Confirmed — no 3rd-party accounting API integration; matches the reference product's own bespoke double-entry ledger.
