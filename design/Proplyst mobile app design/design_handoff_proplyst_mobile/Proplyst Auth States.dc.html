Session expiry wins. If the refresh token fails, the lock screen is skipped and the sign-in screen shows the expired banner with the email prefilled; the biometric preference is kept.
Sign out clears the session and turns biometric unlock off for the device. Next launch is the plain sign-in screen with a confirmation toast.
Fallback is always one tap away: "Use password instead" on the lock screen and inside the Android prompt.
Implementation hooks (no config values)
iOS · SwiftUI · LocalAuthentication LAContext: canEvaluatePolicy → biometryType decides the Face ID / Touch ID label and glyph; errors biometryNotAvailable / biometryNotEnrolled / userCancel map to the states below. Session token in Keychain; biometric-unlock preference is a per-device flag. Sign in with Apple via AuthenticationServices (button shown on iOS only). Google via Google Sign-In SDK.
Android · Jetpack Compose · BiometricManager.canAuthenticate(BIOMETRIC_STRONG) → BIOMETRIC_ERROR_NO_HARDWARE / NONE_ENROLLED / SUCCESS; BiometricPrompt with a negative "Use password" button (system sheet, shown as a mock). Token in EncryptedSharedPreferences / Keystore. Google via Credential Manager. No Sign in with Apple.
Both · Loading disables inputs and shows the spinner inside the primary button; buttons with unmet requirements render at 45% opacity and are not tappable. Errors are inline banners above the actions, never toasts. Copy in the frames is final.

How to drive it
Type any password and tap Sign in → loading → first-login biometric offer.
Password wrong → invalid credentials. Password offline → network failure with Retry.
Google / Apple → provider hand-off screen → same offer.
Enable → system prompt → Security settings with the toggle on. Cancel the prompt to stay unenrolled.
In Security: Lock now → returning-user lock screen. Cancel the prompt there → failed state. Session row → expired sign-in. Sign out → confirm sheet → signed-out sign-in.
Device tweak: switch platform, Face ID ↔ Touch ID, and biometric availability (available / unavailable / not enrolled) to see the settings row change.
