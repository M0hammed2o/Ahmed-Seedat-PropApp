# Technical Debt Register

Distinct from `RISK_REGISTER.md`: a **risk** is something that might go wrong. **Technical debt** here is a deliberate, known simplification or incomplete cutover — a specific, scoped gap between the current state and the target state, taken on knowingly rather than discovered as a surprise. Every item has an owning milestone where it gets paid down; nothing here is open-ended.

## How this register is used

Every item above is either (a) already assigned to a specific `TASKS.md` milestone, in which case it's paid down as a normal part of that milestone's exit criteria, or (b) flagged as "not yet assigned," in which case it must get a milestone assignment before the phase of work it would block is considered complete. Nothing on this list is meant to persist indefinitely — a technical debt item with no paydown plan is really just an unaddressed risk wearing a more comfortable name, and should be re-filed in `RISK_REGISTER.md` if it's ever found drifting that way.
