## 1. The integration-type vocabulary (do not conflate these)

| Term                               | What it means for Proplyst                                                                                                                                                                                                         | Examples found                                                                                                                      |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **Pulse output**                   | The meter closes a contact every N litres/Wh. Needs a counter device to turn pulses into a cumulative number. No data protocol at all.                                                                                              | SANS 1529-1 "pulse-ready" water meters; Eastron SDM120 S0 output; Elster V200 + PR6                                                 |
| **Local Modbus (RTU/TCP)**         | A documented _register map_ read by something on site (gateway/PLC). **Not a cloud API** — a gateway must poll and forward.                                                                                                        | Eastron SDM120M/SDM630, CHINT DDSU666/DTSU666, Schneider iEM3xxx, Carlo Gavazzi EM24/EM340                                          |
| **LoRaWAN network-server integration** | Battery radio sensors → a LoRaWAN gateway → a network server (built into the gateway, or ChirpStack/TTS) → HTTP/MQTT push to our endpoint. Payload is decoded with a published codec.                                       | Milesight EM300-DI, UC300/UC100, Kamstrup flowIQ 2200 OMS-LoRaWAN variant, Eastron SDM230-LoRaWAN                                   |
| **MQTT**                           | Device/gateway publishes to a broker _we_ operate (or to a vendor broker).                                                                                                                                                        | Shelly Gen2+ (own broker, TLS/mTLS), Milesight gateway MQTT, Teltonika TRB246                                                       |
| **Public REST API**                | A cloud API any customer can use without a commercial contract.                                                                                                                                                                    | Shelly Cloud Control API — single-account, **1 call/s** limit (not usable as a multi-tenant SaaS backbone)                         |
| **Private partner API**            | Cloud API gated by a commercial agreement / approval.                                                                                                                                                                              | Shelly Integrator API ("Licenses for personal use are not provided"); Kamstrup READy "API Access" (READy-hosted customers only)    |
| **Proprietary cloud-only**         | Data only visible in the vendor's portal/app; no API found.                                                                                                                                                                        | Citiq Prepaid, Recharger, Smart-View Technology, Utility Systems, Lesira-Teq consumer portal                                        |

**Conclusion that drives the architecture:** the cheapest, least-locked-in paths are all _push_ paths
(LoRaWAN network server → HTTP webhook; Shelly → HTTP/MQTT; Modbus gateway → HTTP JSON). None of them needs a
vendor cloud account, a partner agreement, or a stored vendor credential. **No SA prepaid/submetering vendor
exposes a public API** (Citiq, Recharger, Conlog, Hexing, Landis+Gyr, Smart-View — none found; absence of
evidence, not proof).

### 2.2 Water notes

- **EM300-DI** (Verified on [product page](https://www.milesight.com/iot/product/lorawan-sensor/em300-di)): dry-contact/reed input up
  to 2 kHz, 250 µs min pulse; 4000 mAh battery ≈ 5 years at 10-min interval; 1,000 records stored on device
  (lets a gateway outage be back-filled). MiRO showed 50+ in stock (Johannesburg). Installation is strap-on beside
  the meter with a 1 m cable; **no mains power** — the decisive advantage over Shelly in SA, where water meters
  usually sit in an outdoor boundary box.
- **Kamstrup wM-Bus** telegrams are AES-encrypted; keys come from Kamstrup's Encryption Key Service. Lock-in moves
  from protocol to key management. SA stock of the LoRaWAN variant 02K73A: **Unknown** — ask UtilityPal.
  Kamstrup announced that "a smart water meter passed test in South Africa" ([news](https://www.kamstrup.com/en-en/news-and-events/news/smart-water-meter-passes-test-in-south-africa)); which model: Unknown.
- **Network:** a Milesight gateway's built-in network server has no platform fee (Likely). The TTN community
  network is free but has a fair-use cap (30 s uplink airtime / 10 downlinks per device per day) and **no SLA**
  ([TTN forum](https://www.thethingsnetwork.org/forum/t/the-things-network-fair-use-policy/47689)) — not for
  billing-grade data. Sigfox SA won National Treasury tender RT29 for ~15 million _municipal_ smart water meters
  ([RCR Wireless 2024-06](https://www.rcrwireless.com/20240606/internet-of-things-4/sigfox-wins-major-smart-water-meter-contract-in-south-africa)) — relevant to municipal main meters, not private submeters.
- **Installation/compliance:** a registered plumber fits the meter; the pulse counter is non-invasive. City of
  Cape Town requires private isolation valves and **a meter per unit** in multi-unit properties, owner-installed
  and maintained, measuring "in accordance with the Trade Metrology Act"; exemption needs a plumber's report plus
  body-corporate minutes ([CoCT exemption page](https://www.capetown.gov.za/City-Connect/Apply/Municipal-services/Water-and-sanitation/apply-for-exemption-from-private-isolation-valves-and-sub-metering/Apply%20for%20exemption%20from%20private%20isolation%20valves%20and%20sub-metering)) — from snippets; by-law PDF not fetched. Other metros: Unknown.

### 3.2 Electricity notes

- **Shelly Gen2+** (Verified from docs): RPC over HTTP/WebSocket/MQTT/UDP; MQTT topics `<id>/rpc`,
  `<id>/events/rpc`, `<id>/online`; `EMData` exposes perpetual Wh counters (`total_act`, `total_act_ret`,
  per-phase) and 1-minute history. Devices can run on-device scripts that `HTTP.POST` to any URL — which is how
  Proplyst ingests Shelly data without operating an MQTT broker in Phase 1. SA channel: Nology says it is a
  value-added distributor ([nology](https://www.nology.co.za/product/products/shelly-pro-3em-120a-detail)); ShellySA
  shows no prices.
- **Shelly is CT-clamp monitoring-grade, not MID.** Present Shelly data as _consumption monitoring_, never as the
  basis for tenant electricity billing.
- **Eastron SDM120M defaults to 2400 baud**, most other meters 9600 ([ESPHome](https://esphome.io/components/sensor/sdm_meter/))
  — a mixed RS485 bus needs every meter set to one baud rate and unique slave IDs. RS485 segments ≈32 unit loads
  without repeaters (standard RS485, Likely) → a 50-unit block needs two segments or a repeater.
- **UC300/UC100** read 32 Modbus channels of 1–2 registers each → ≈30 kWh registers per controller (Derived).
- **SA prepaid/submetering vendors:** Citiq (landlord portal + app, no API found; service fee ≈8.45–8.75 % + VAT per
  token [S, review sites]); Recharger (STS vending, no API); Conlog (vending web services for utilities/POS =
  partner); Hexing / Landis+Gyr (utility head-end, IDIS = partner); Smart-View (demo-only). **All lock-in.**

### 3.3 Electrical installation & resale compliance

- **CoC (Verified):** Electrical Installation Regulations 2009 — only a registered person issues a Certificate of
  Compliance; any addition/alteration needs one ([acts.co.za](https://www.acts.co.za/occupational-health-/ei2009_nr242_7__certificate_of_compliance)).
  DIN-rail meters, CTs and RS485 wiring in a DB are alterations. A "single-phase tester" registration cannot
  certify three-phase work (Likely).
- **Cape Town Electricity Supply By-law s20 (Verified)** ([by-law](https://openbylaws.org.za/akn/za-cpt/act/by-law/2010/electricity-supply/eng@2018-08-11)):
  resold electricity must be measured by a submeter "of a type which has been approved by the South African Bureau
  of Standards"; resale tariff no less favourable than the City's; monthly tenant accounts at least as detailed as
  the City's. Ekurhuleni's by-law reportedly has equivalent SABS-approval and tariff-cap wording [S].
- **NERSA Guidelines on Electricity Resale** (NERSA-467-58, [Eskom-hosted copy](https://www.eskom.co.za/distribution/wp-content/uploads/2021/06/GuidelinesElectricityResale.pdf), issue date Unknown):
  resale tariff identical to the licensed distributor's approved tariff (§8.3); **"No additional costs, such as the
  cost for meter reading, vending, billing and compliance services may be recovered from the customer" (§8.5)**;
  bills must show kWh, tariff, cycle, total, contact (§6.1).
- **MID / IEC 62053 / EN 50470 are not SA type approval.** Whether MID-only Eastron/CHINT units satisfy "SABS-approved"
  for tenant rebilling is **Unknown** — a legal/municipal check is required before Proplyst offers electricity
  rebilling (monitoring is unaffected).

### 4.1 Recommended initial launch stack (Phase 1)

- **Water: Milesight EM300-DI + Milesight UG65 (multi-unit) / UG63-LTE (single property), on SANS 1529-1
  pulse-ready meters.** Reasons: in stock in SA with prices on the page; payload codec published (GPL-3.0);
  battery-powered (no mains at the meter box); the gateway's built-in network server pushes HTTP to Proplyst, so
  there is **no vendor cloud, no partner agreement, no platform subscription, and no stored vendor credential**.
- **Electricity: Shelly Pro 3EM / Pro EM-50 / EM Gen3 for monitoring (fastest), and Eastron SDM120M/SDM630 via a
  Modbus→HTTP gateway for billing-grade multi-unit sites.** Shelly has a public local API and pushes to our HTTP
  endpoint from an on-device script; Eastron is MID-certified and widely stocked by UtilityPal.
- Proplyst's ingestion is **protocol-neutral**: one endpoint, per-provider adapters (`milesight_lorawan`,
  `shelly_gen2`, `generic_json` for Modbus gateways, `simulator`). Adding Kamstrup LoRaWAN or SDM230-LoRaWAN is a
  new decoder, not a new pipeline.

### 5.1 Cross-cutting findings

- **Private/third-party submeter readings for municipal billing:** no official source says they are accepted;
  every channel asks for the _municipal_ meter number; several reserve the right to audit/inspect. **Likely NO.**
  Therefore Proplyst only ever submits readings **of the official municipal meter**, obtained by an owner photo or
  by a pulse counter fitted to that municipal meter (flagged "device-derived — verify against dial").
- **Portal automation:** e-Joburg terms prohibit "data mining, robots or similar gathering and extraction tools"
  (cl. 8.2) and password sharing (cl. 5.1) ([terms](https://edit.eservices.joburg.org.za/pages/Terms.aspx));
  e-Tshwane requires a **written mandate** for agents and calls storing a password "prima facie negligence"
  ([terms](https://e-tshwane.co.za/terms-and-conditions)); Siyakhokha has the same mandate clauses. **Proplyst
  will not automate any municipal portal.**
- **Received ≠ accepted:** CoJ "may use"; eThekwini audits and its own readings take precedence; Tshwane disregards
  late readings; Cape Town "not compulsory". A sent email is recorded as _sent_, and acceptance is confirmed only
  from the next municipal bill.
- **POPIA (Act 4 of 2013):** an emailed reading pack (account number, name, address, possibly ID number, property
  photo) is personal information. Proplyst acts as operator: lawful basis (s11), safeguards (s19), written operator
  terms (s21), cross-border conditions (s72). Misaddressed email is an unauthorised disclosure → recipients must
  be explicitly approved, and **tenant data is never included**. Polokwane refuses to email statements to
  unregistered addresses citing POPIA.
- **Water Services Act s25(2):** a landlord acting as water-services intermediary may not charge tariffs outside
  prescribed norms ([s25](https://source.acts.co.za/water-services-act-1997/25__duties_of_water_services_intermediaries.php)).

### 5.2 Product consequences (adopted in the architecture)

1. **Default mode is "approval required"**; "automatic" exists but only for recipients the owner has explicitly
   authorised, is disabled platform-wide by default (`SMART_UTILITY_AUTO_SUBMISSION_ENABLED`), and is never
   offered for app-only municipalities.
2. The municipality directory stores **only addresses verified above, each with its source URL and verified
   date**; ambiguous ones (eThekwini's `revlineresponse@`, Polokwane's contractor domain) are shown as
   "unconfirmed — enter your own" rather than pre-filled.
3. App/portal-only municipalities (Ekurhuleni, Stellenbosch, NMB, Buffalo City) get "reminder + prepared values +
   CSV/print", not email.
4. Submission windows are owner-configured per property (billing day + lead days), never guessed.
5. Tenant rebilling is kept separate from municipal submission (NERSA §8.5 bars recovering meter-reading/billing
   costs from tenants).
